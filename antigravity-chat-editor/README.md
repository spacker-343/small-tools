# Antigravity AI 回复即时编辑器

在主聊天、全屏聊天及右侧子 Agent / Swarm Worker 的 AI 回复旁添加“编辑”入口。编辑框直接展开在消息里，**点击“保存”立即生效，不退出、不重启 Antigravity，也不重启会话服务。**

## 使用

1. 首次安装运行 `安装.cmd`；普通安装需要应用处于退出状态，以接入预加载桥接。已经安装的补丁会在应用下次启动时自动加载。开发修复可以在当前运行进程中加载，不需要每次保存都重新加载插件。
2. 打开主聊天或侧栏中的一条已完成的 AI 文字回复，点击“编辑”。
3. 修改正文，点击“保存”。界面立即显示修改后的内容，接下来发出的模型请求使用修改后的正文。

保存成功保持静默，不显示悬浮通知；只有保存失败时，编辑框内显示简短错误。
4. 发送下一条消息后，可运行 `核验请求.cmd` 检查最近一次包含编辑的实际转发记录。
5. 再次编辑并改回原文，即可移除此条替换规则。

编辑后的正文会渲染 Markdown，包括标题、粗体、列表、引用、行内代码、围栏代码块、表格和链接；再次编辑以及发送给模型时保留原始 Markdown。原始 HTML 不作为可执行内容渲染。运行需要 Windows；安装与诊断脚本需要 Python 3.10+。应用内运行使用 Antigravity 自带的 Electron / Node，不需要单独安装 Node 或 npm。

## 实际模型请求如何修改

插件调用 Antigravity 本地服务的 `SetCloudCodeURL`，将原本的 Cloud Code 请求入口切到本机 `127.0.0.1` 的随机端口。插件在本机内存中检查模型请求，再通过 HTTPS 转发到 Antigravity 原先使用的服务地址，不引入第三方转发服务，不修改系统代理，不安装证书。

替换规则按**当前会话 ID + 原始消息 ID**保存。出站请求按 `request.labels.cascade_id` 和 `agent/<会话ID>/...` 请求标识核对所属会话，只替换 `model` / `assistant` 角色中的指定正文，不替换用户消息或思考正文。相同文本多次出现时按消息顺序定位；范围不足或无法可靠定位时阻止发送，并要求重新保存编辑。

部分已完成的原生回复没有 `messageId`；这类回复使用原生 `modelApiContentId` 作为备用标识，气泡编辑、保存和压缩摘要重建共用同一定位规则。两种标识都缺失时不提供编辑入口，避免编辑到其他消息。

侧栏中的继承消息按侧栏会话保存规则，不修改父会话的规则。已经发出的请求不会追溯修改。保存时正在进行的请求继续使用其已发送的内容，后续请求应用新规则。

**此版本不直接改写 Antigravity 原生数据库。** 原生导出、旧调试记录和其他未经过本插件的客户端仍可能显示原文；插件保存自己的编辑记录，并修改当前界面预览和实际出站模型输入。这样可以避免运行中的服务继续使用旧数据库缓存，也无需为了清缓存而重启。

## 已验证的链路与范围

在本机 Antigravity 2.34.0 / Electron 44.9.1 的独立测试会话中，已完成实际模型请求实验：

1. 让模型回复唯一测试标记；
2. 在发出下一次请求前，将历史 AI 正文中的标记替换成另一个值；
3. 询问模型上一条 AI 回复里的标记；
4. 模型返回修改后的标记，整个过程保持同一个 Antigravity 和会话服务进程运行。

即时编辑版还在真实 `/c/<会话ID>` 页面完成了点击编辑、保存、预览更新和再次请求模型的验证。测试结果保存在本机 `.local/acceptance.json`；页面 IPC、实际转发和模型返回值均通过，应用与会话服务进程 ID 保持不变。

压缩摘要修复另在包含原生 checkpoint 的独立会话中验证：编辑已被摘要覆盖的回复后连续续聊两次，模型均返回修改后的标记；实际转发记录为 `summary-rewritten`、HTTP 200，`listExperiments` 也返回 200。验收保存在本机 `.local/acceptance-compaction.json`，应用及会话服务进程保持不变。

当前支持经 Antigravity Cloud Code `streamGenerateContent` / `generateContent` JSON 路径发送的模型请求；本机 Gemini 路径已验证。其他模型厂商、云端会话或未来改变协议的路径需要分别核验，不能仅凭界面显示修改就宣称链路已验证。

目标回复进入压缩摘要后，插件会定位本次请求实际使用的摘要，从原生历史中应用用户修改并重建摘要，再替换请求中的旧摘要。新摘要还会保留修改后 AI 回复的完整原文，供模型继续对话使用。原生历史和原生摘要文件不直接改写。

第一次遇到这份摘要时，会额外调用当前模型重建摘要；长历史会分段处理，因此首次继续可能比平时慢。结果保存在本机缓存，后续请求复用；下一次压缩会优先复用已经校验过的修订摘要，只处理新增历史。重建中断后可从已完成的分段继续，不会因此删除编辑规则。模型服务、网络或无法识别的摘要格式出错时，会保留编辑并明确返回错误，不会偷偷发送旧摘要。

工具调用、图片、思考和签名结构不作为可编辑正文；匹配正文携带的旧签名会移除，其他工具及思考结构保留。账户和配置查询（包括 `listExperiments`）直接转发，不应用聊天编辑规则。

## 更新与兼容性

没有固定 Antigravity 版本白名单。安装时读取当前版本用于显示，根据实际协议描述符、前端气泡/侧栏标记和本地服务能力判断是否兼容。未来若底层结构改变，需要适配，不能保证任意未知版本都自动兼容。

官方更新会覆盖 `app.asar`。之后通过 `启动Antigravity.cmd` 启动，脚本会检查并在兼容时恢复补丁。也可重新运行 `安装.cmd`。保存聊天内容本身始终不触发应用重启。

`antigravity-fork` 修改 `language_server.exe`，本工具的持久加载补丁修改 `app.asar`，不会覆盖 Fork 工具的二进制修改。

## 本机数据、核验和卸载

- `.local/edits.json`：编辑规则，包含原文与修改后的正文。
- `.local/backups/edits/`：上一次规则的备份。
- `.local/last-forward.json`：最近一次与编辑相关的转发证据，只记录消息键、正文哈希、时间和 HTTP 状态，不保存令牌和完整网络报文。
- `.local/summary-cache.json`：依据修改后历史重建的摘要、分段进度及复用校验信息；不保存认证令牌。
- `.local/backups/application/`：安装前的程序备份。
- 旧版本产生的数据库备份保留在 `.local/backups/conversations/`，即时编辑版不再直接修改原生数据库。

`forwarded` 且对应消息为 `rewritten` 或 `summary-rewritten`，表示实际出站 JSON 中已替换正文或重建相关摘要，并记录上游 HTTP 响应；这不等同于模型回答一定采纳修改。目标回复被截断且无法定位、摘要格式无法识别，或模型请求路径尚未适配时，会记录 `blocked` 并保留编辑，避免发送无法可靠处理的旧内容。

`卸载.cmd` 在应用退出后还原原始加载文件；应用已更新时不会用旧程序覆盖新版本。编辑规则和备份保留在本机，均被 Git 忽略。插件不修改原生聊天记录，卸载后原生界面显示原文。

## 开发检查

`检查兼容性.cmd` 只读检查当前安装。自定义安装路径使用 `python -X utf8 install.py check --app "D:\Apps\Antigravity"`，其他安装动作同样接受 `--app`。

```text
npm install
npm test
```

测试覆盖气泡内编辑、主聊天和侧栏定位、`/c/<ID>` 页面权限、即时保存不退出应用、会话隔离、重复正文定位、思考及用户消息保留、压缩摘要重建与精确定位、连续压缩和中断恢复、配置请求放行、签名和缓存处理、未知结构拦截，以及安装包回读和跨版本能力检测。

`renderer.source.js` 是可维护的界面源代码，`markdown.js` 使用 [markdown-it](https://github.com/markdown-it/markdown-it) 解析 Markdown，并通过 [DOMPurify](https://github.com/cure53/DOMPurify) 清理生成的 HTML。`npm run build` 将代码和依赖打包成自包含的 `renderer.js`，同时生成 `renderer.licenses.txt`；发布时保留这两个生成文件，使用者无需安装依赖或从 CDN 加载脚本。
